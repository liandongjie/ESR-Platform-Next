# 指标目录基线

Phase 1A 先固定“业务指标 ↔ GeoTIFF 文件”的数据契约，不在业务代码中散落文件名。

| code | 指标 | GeoTIFF | 旧版默认选中 | 旧版默认权重 |
| --- | --- | --- | --- | ---: |
| PM25 | 细颗粒物 (PM2.5) | `PM25.tif` | 是 | 30% |
| AQI | 空气质量指数 (AQI) | `AQI.tif` | 是 | 40% |
| NDVI | 归一化差值植被指数 | `NDVI.tif` | 是 | 30% |
| hwmd | 河网密度 | `hwmd.tif` | 否 | 0% |
| rkmd | 人口密度 | `rkmd.tif` | 否 | 0% |
| xxmd | 学校密度 | `xxmd.tif` | 否 | 0% |
| jmdmd | 居民点密度 | `jmdmd.tif` | 否 | 0% |
| xspb | 刑事批捕率 | `xspb.tif` | 否 | 0% |
| xsqs | 刑事起诉率 | `xsqs.tif` | 否 | 0% |
| gyfb | 官员腐败指数 | `gyfb.tif` | 否 | 0% |
| fmyl | 垃圾焚烧负面舆论占比 | `fmyl.tif` | 否 | 0% |
| fmts | 环境投诉负面数量占比 | `fmts.tif` | 否 | 0% |

## 为什么先保留旧 code

旧项目的后端接口和分析参数已经使用 `PM25`、`AQI`、`rkmd` 等 key。Phase 1A 的目标是先验证真实数据和旧算法契约，继续使用这些稳定 key 可以避免“文件名迁移”和“业务语义重命名”同时发生。

后续如果希望 API 使用 `population_density` 这样的英文语义 code，可以增加显式 alias，而不是直接破坏已有数据映射。

## 当前默认权重的边界

目前能从旧 React 版本直接核实的默认配置只有：`PM25=30`、`AQI=40`、`NDVI=30`，且默认只选中这三项。其余九项不是“权重永远为 0”，而是旧界面默认未选中；用户选择后可以自行配置权重。
